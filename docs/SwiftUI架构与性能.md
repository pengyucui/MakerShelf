# MakerShelf 原生 SwiftUI 架构与性能说明

## 实现范围

当前原生客户端使用已确认的 Appica V2 设计，旧方案 A 与 Native Glass 网页仅保留作历史参考。以 macOS 14、Swift 5.9 语言能力和 Xcode 15 工程格式为基线，使用系统 SwiftUI、Observation、AppKit、Foundation、ImageIO，不引入第三方运行依赖。

界面是真正的 SwiftUI 视图，没有 WKWebView 包装网页。AppKit 用于原生目录 / 文件选择和应用生命周期事件；模型插画沿用网页稿中的原创图形，预先转换成原生 PNG 资源，运行时不解析 SVG。

当前交付包括原生工程、页面、模型状态、查询、图片管线、站点登录页、公开模型解析、真实归档写入、本地模型创建和本地偏好。指定作者公开作品可以匿名预览；当前账号收藏 / 作品与 3MF 下载按需读取对应站点登录会话。站点无公开官方 API，客户端按 MakerWorld 当前网页接口适配。

指定作者的用户名搜索和发布列表始终使用匿名请求，不复用网页 Cookie 或令牌。这样在网页同源接口受防护、请求回退到 Bambu Lab 云端接口时，不会把网页会话错误地作为云端 Bearer 授权；用户确认清单并开始下载模型文件后，下载队列才恢复对应站点会话。

## 模块职责

| 模块 | 职责 | 执行位置 |
| --- | --- | --- |
| `AppState` | 页面与弹窗路由，协调导入、目录与队列 | 主 actor |
| `LibraryStore` | 筛选条件、分页结果、请求代次、加载和错误状态 | 主 actor |
| `ModelCatalog` | 本地索引解码、搜索索引、过滤、排序、分页 | 独立 actor |
| `ImportStore` | 导入表单校验、取消、站点模型清单选择 | 主 actor |
| `LocalModelStore` | 本地模型创建/编辑表单、现有归档回填、文件类型校验与保存状态 | 主 actor |
| `LocalModelCreationView` | 双栏创建与编辑、拖放、系统文件选择与实时卡片预览 | 主 actor |
| `LocalModelImporter` | 复制自有模型与图片、生成介绍和元数据、原子落盘 | 独立 actor |
| `ModelSourceProviding` | 获取清单的可替换契约，现为 MakerWorld 适配器 | 异步服务 |
| `MakerWorldClient` | 双站点 HTTP、模型详情、列表、文件下载 | 独立 actor |
| `SessionStore` | 登录态、按需钥匙串会话、Cookie / Token | 主 actor |
| `DownloadStore` | 去重、等待队列、并发调度、暂停恢复取消 | 主 actor，仅维护状态 |
| `DownloadJob` | 单个任务的进度与状态 | 主 actor，单独观察 |
| `DownloadExecuting` | 下载执行契约，写入归档目录 | 异步服务 |
| `ImagePipeline` | 缩略图缓存、合并相同请求 | 独立 actor |
| `ThumbnailDecoder` | 文件读取、ImageIO 缩略解码 | 并发数为 2 的后台队列 |
| `PreferencesStore` | 本地偏好与文件夹书签 | 主 actor |

主线程负责界面和轻量状态更新，不在视图 `body` 中读文件、解析 JSON 或执行模型集合排序。

## 本地模型创建与编辑

统一添加窗口提供「本地模型」来源，采用 Appica V2 双栏 Sheet：左侧编辑模型名称、作者、副标题、分类、模型文件、展示图片、文字介绍、材料和预估打印时间，右侧实时预览模型库卡片与归档路径。第一张图片作为封面；没有图片时使用轻量占位图，不额外生成大图。

本地模型的 Inspector 底部固定提供编辑入口，卡片与列表行也可用右键打开，继续复用同一表单。编辑时从归档路径回填文件 URL，保存服务先在归档根目录构建临时副本，完成文件、`description.html` 与 `metadata.json` 写入后才替换旧目录；替换失败会恢复备份。编辑保持模型 ID、归档路径与排序位置不变，并通过更新时间触发封面重新解码。

模型文件可以直接拖放，也可以通过 SwiftUI `fileImporter` 调用系统文件选择器，支持 3MF、STL、OBJ、STEP、STP、GCODE 和 AMF；图片交给系统图片类型过滤。所有入口统一进入 `LocalModelStore` 校验和去重。视图最多同时展开 12 个模型文件名；更多文件仍会全部复制，避免超大选择集一次创建大量 SwiftUI 行。图片列表使用横向 `LazyHStack`，缩略图与右侧预览继续复用既有图片管线。

`LocalModelImporter` 在独立 actor 中串行执行文件操作。它先写入归档根目录下的专用临时目录，复制完成并生成 `description.html`、`metadata.json` 后再移动为最终目录；失败只删除本次临时目录，不改动来源文件。文件名会清理非法路径字符并处理重名，索引中只存相对归档路径。模型来源使用独立的 `ModelOrigin.local`，所以重启后不会被演示数据过滤，也不会混入中文站或国际站筛选。

## Appica V2 的原生落地

- NavigationSplitView 承接原生分栏与侧栏折叠；侧栏建议宽度 218 pt，只保留模型库、下载任务、设置。
- 来源筛选只保留在模型库顶部，状态和排序常驻，作者与分类收入原生 Popover。
- 使用真实 macOS 窗口控制按钮；窗口默认 1560 × 980，最小 1080 × 720。
- 网格最小列宽 240 pt，4:3 底板决定封面尺寸，图片覆盖于底板之上；文字信息区固定高度，图片和长标题不能改变行高。
- 内容宽度达到 1060 pt 时显示可关闭的 320 pt Inspector；更窄时以原生 Sheet 查看详情。详情转编辑或任务页通过 Sheet 的 onDismiss 衔接，避免争用模态窗口或在页面移除时丢失回调。
- 模型库只保留一份惰性网格；工具栏利用 ViewThatFits 换行，分页入口在内容底部。
- Appica V2 采用雾灰背景、白卡片、深墨色按钮、细描边与轻阴影，并使用动态颜色适配深色外观。
- 侧栏毛玻璃响应系统“减少透明度”，卡片、详情和表单不重复叠加模糊材质。
- Inspector 提供多图切换、完整图文介绍与文件清单、文字选择、归档状态和固定操作区；访达与编辑按钮纵向排列，任务状态复用 ModelLibraryStatus。
- 图文介绍复用 DescriptionBlocks，优先解析已改写为本地路径的 descriptionHTML，过滤 HTML 标题、样式、脚本及注释。正文与插图按原顺序展示，图片复用缩略图管线；没有正文时回退到摘要。不会执行网页脚本，也不还原复杂网页排版。
- ⌘K 请求通过 LibraryStore 保留到模型库挂载，避免从其他页面切回时丢失焦点请求。

## 钥匙串访问策略

应用启动只创建空的内存会话状态，不读取中文站或国际站钥匙串。会话写入数据保护钥匙串（`kSecUseDataProtectionKeychain`），由当前 App 身份独占，读取时不再弹出文件钥匙串的「允许 / 始终允许」。每个站点在进程内只恢复一次，之后设置页使用内存状态。旧版文件钥匙串条目会在第一次成功读取后迁移并删除。打开模型库、浏览本地归档不会访问钥匙串。

## 模型列表与查询

### 稳定身份和惰性视图

模型 ID 包含站点前缀，例如 `cn:1`，跨站不自动合并。列表使用模型 ID 作为 `ForEach` 身份，避免重新筛选时生成随机 ID，触发所有卡片重建。

网格采用 `LazyVGrid`，列表采用 `LazyVStack`，不在一个普通 `VStack` 中创建全部卡片。每次返回最多 120 条；用户主动加载下一页。分页限制单次发布量，但多次加载仍会累积轻量模型记录，并不等于无限数据的恒定内存方案。

### 搜索合并和取消

`LibraryView.task(id: query)` 随筛选条件变化取消上一轮任务。开始查询前等待 250 ms，连续输入时只执行最后一次有效查询。

请求同时记录递增代次和查询快照。actor 返回后检查取消状态、代次和当前条件，旧结果不会覆盖新条件。加载更多也使用同一代次机制。错误单独展示，取消不当作用户错误。

### 后台索引和分页缓存

`ModelCatalog` 首次需要时才读取持久化模型索引；每条记录预计算标准化的标题、副标题和作者搜索文本。过滤时不反复构造搜索字符串。

过滤循环定期检查取消。过滤和排序放在 actor 中，排序结果按当前查询缓存；下一页从结果中切片，不重复执行整个过滤和排序过程。模型归档状态改变时再使缓存失效。

**边界：** 当前目录仍一次载入全部元数据并在内存中索引。若接入数十万模型，应替换为数据库索引和真实分页，不声称本实现已经具备这种规模的实测能力。

## 图片管线

### 缩略解码

图片尺寸桶为 160 / 320 / 640 / 1280 像素。卡片请求 640；详情请求 800，归入 1280 桶；图库缩略图请求 200，归入新增的 320 桶；紧凑列表和任务行使用 160 桶。ImageIO 直接生成目标尺寸缩略图，避免先解码完整图再在主线程缩放。

缓存键包含图片来源、尺寸桶和归档版本，窗口缩放不会不断生成只有几像素差异的新条目。本地编辑成功时清空共享图片缓存，视图任务使用归档更新时间重新加载；在途请求也按版本隔离，旧解码完成后不会被新版本视图复用。

### 缓存和并发

- `NSCache` 设置 64 MiB 总成本和 128 条软限制；成本按实际像素缓冲计算。
- 同一缓存键的并发请求共享任务，避免卡片与 Inspector 重复读取相同尺寸图片。
- 后台图片解码队列最多并发 2 个操作。
- 每次解码使用自动释放池，及时释放中间 ImageIO 对象。
- 卡片离屏释放视图持有的图片引用；可见性进入任务标识，返回时重启加载并复用缓存，避免弹窗遮挡后留下空白封面。
- 单个视图取消只丢弃自身结果，不取消其他视图共享的解码任务。

**边界：** NSCache 限制是可回收软上限，不是整个应用内存硬上限。可见视图、在途解码、数据索引和系统渲染缓存都占用额外内存。支持应用资源、归档图片和远程图片，但尚无独立的远程图片磁盘缓存。

`Thumbnail` 的 `@unchecked Sendable` 只包装创建后不再修改的 CGImage；解码器的相同标记仅覆盖线程安全的 OperationQueue。可变缓存由 actor 隔离，不把可变 NSImage 跨线程共享。

## 下载调度

### 独立观察

每个任务是单独的 `@Observable DownloadJob`。任务行读取它自己的进度；父列表只读取任务引用数组。侧栏读取缓存后的待完成计数，不读取各任务进度。

底部 DownloadActivityBar 只读取队列与任务阶段，具体进度由独立的 DownloadActivityContent 观察；模型卡片通过模型 ID 字典定位对应任务，ModelLibraryStatus 只读取阶段。进度变化不替换整个任务数组或任务索引，也不会触发模型目录筛选。任务完成后才通知模型库更新真实归档状态。

摘要只在模型最新任务中按运行、等待、暂停、失败、部分完成的优先级选取，历史失败记录保留在任务页。详情使用同一任务索引提供状态与队列入口，不在详情内新增一套下载调度逻辑。

### 并发、去重和排队

- 默认并发 2，设置范围 1–3。
- 降低并发上限时已有任务继续运行，新的等待任务暂缓启动。
- 以来源模型 ID → 任务 ID 的预约字典完成去重，已暂停任务也保留预约。
- 等待任务采用 ID 数组与消费游标，任务 ID 通过字典定位，避免每次调度扫描全部历史。
- 队列前缀批量回收，避免连续 `removeFirst` 搬移数组。
- 批量导入后只发布一次任务集合变更。
- 暂停和取消时移除运行 token 并取消对应任务；恢复生成新的 token。旧回调不得更新新一轮任务。
- 重试历史记录同样检查预约所有权，不能与新创建的同模型任务并发。
- 只有运行中的任务拥有等待循环，界面没有全局每秒扫描所有模型的计时器。

真实执行器按「获取信息 → 模型文件 → 介绍 → 图片」更新进度。暂停会取消当前请求；继续时跳过已经存在的本地文件。退出或主窗口消失时停止运行任务；下次启动不恢复队列，已写入的归档和 `library.json` 会保留。

### 接入真实下载时必须补齐

执行器需要支持实际请求取消、文件临时路径、分段写入、大小/校验值验证、限速和站点错误分类。真实任务产生高频字节回调时，应在执行器中同样合并到有限 UI 更新频率。

需要持久化等待、进行中、部分完成和失败状态。恢复时校验临时文件与远程版本；介绍或图片失败应标记部分完成，不能把模型文件完成误报为整个归档完成。

## 本地目录与设置

使用 NSOpenPanel 的异步回调选择文件夹，保存安全作用域书签到 UserDefaults。应用下次打开解析书签，失效时提示重新选择，不把失效权限当成有效目录。

当前默认没有预建归档目录，也不会自动创建模型文件。正式执行器使用该目录时，必须在每次读写期间成对调用 `startAccessingSecurityScopedResource` 与 `stopAccessingSecurityScopedResource`。

并发数、首选格式和目录授权会保存；首选格式会传给现有下载执行器。模型元数据保存在 library.json，登录会话保存在钥匙串；任务历史仍只保存在内存。

工程启用应用沙盒、用户选择文件夹读写权限、应用作用域书签权限和网络客户端权限。登录会话保存在钥匙串，不写入归档目录，也不保存账号密码。

## 检查情况与性能验证边界

遵照用户要求，没有编译、运行测试用例、启动应用或提交 Git。已完成：

- 原生工程与权限清单的 plist 格式检查。
- 源码文件与构建阶段、资源目录与示例资源名的静态对应检查。
- 任务预约、取消代次、暂停恢复和查询过期结果的代码走查。
- 中文说明与原生 / 网页历史版本边界核对。

静态检查不能替代 Swift 编译、真实运行、签名验证或性能测量。因此当前交付不附带“编译通过”“某个 FPS”或“内存稳定在某值”的承诺。

后续如需实测，使用 Release 配置与 Instruments 的 Time Profiler、Allocations 和 SwiftUI 相关工具，重点观察快速滚动、连续搜索、反复缩放窗口、批量导入、同时完成多个任务、快速暂停恢复与关闭窗口。数据规模从真实使用量逐步扩大，测量前不提前设定已达标结论。

## 实现依据

使用 Observation 做按读取属性跟踪，与 Apple 的 [Managing model data in your app](https://developer.apple.com/documentation/SwiftUI/Managing-model-data-in-your-app) 和 [Discover Observation in SwiftUI](https://developer.apple.com/videos/play/wwdc2023/10149/) 说明一致。

惰性网格延迟创建所需子视图，参见 [LazyVGrid](https://developer.apple.com/documentation/swiftui/lazyvgrid)。图片按显示尺寸缩略使用 [kCGImageSourceThumbnailMaxPixelSize](https://developer.apple.com/documentation/imageio/kcgimagesourcethumbnailmaxpixelsize)。这些机制是优化基础，实际效果仍需依具体数据与设备测量。
