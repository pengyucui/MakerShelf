# MakerShelf 功能梳理与去重

## 核心范围

从 MakerWorld 中文站和国际站获取本人收藏、本人发布内容、指定作者公开作品或单个链接对应的模型，下载后在本地查看模型文件、原始介绍与图片。

这份文档记录功能去重后的职责。现已按 Appica V2 设计调整 SwiftUI 原生实现，并保留站点登录页、模型链接解析和本地归档写入。收藏 / 作品批量列表与部分文件下载仍取决于登录会话和站点接口稳定性。

## 重复项处理

| 原有功能 / 入口 | 问题 | 整理结果 |
| --- | --- | --- |
| 同步收藏、新增下载、导入窗口里的我的收藏 | 多个名称进入同一套下载流程 | 统一“添加模型”；本人收藏是用户导入条件之一 |
| 侧栏模型来源、模型库顶部来源筛选 | 都是在同一模型列表中过滤来源 | 删除侧栏中文站 / 国际站 / 本地模型三个入口，只保留顶部筛选 |
| 指定账号、作者作品 | 都通过用户 ID 或主页定位用户，只是获取内容不同 | 合并“用户主页”；分别选择目标用户和获取内容 |
| 全部模型、已下载 | 同一模型列表的两个筛选视图 | 合并“模型库”，提供全部 / 已下载 / 未下载筛选 |
| 关注的作者、作者搜索 | 原型没有关注管理，仅按作者查看已有模型 | 删除独立作者页，保留作者筛选和关键词搜索 |
| 本地我的收藏、卡片心形按钮、站点收藏 | “收藏”同时表示两种数据，容易误认为修改源站收藏 | 删除额外的本地收藏；“收藏”只表示导入的站点内容 |
| 桌面灵感、模型分类 | 预设集合实际只是按分类过滤，未提供集合管理 | 移除预设集合，保留分类筛选 |
| 顶栏设置、工作空间按钮、站点卡片、账号管理 | 同一设置能力散落多个入口 | 设置页集中管理双站点连接；侧栏不再展示来源或连接菜单 |
| 导入时勾选介绍/图片、设置中的媒体开关 | 重复决定归档内容，也容易遗漏用户明确需要的信息 | 固定完整归档：文件 + 介绍 + 图片 |
| 查看本地归档按钮、归档信息标签 | 按钮只切到同一个标签，没有独立能力 | Inspector 保留归档标签；真实归档可直接在访达中显示 |

## 最终结构

```text
MakerShelf
├── 模型库
│   ├── 搜索 / 来源 / 作者 / 分类 / 下载状态
│   ├── 网格或列表
│   └── 右侧 Inspector：图片、介绍、文件、归档信息
├── 下载任务
│   └── 进度、暂停、继续、完成记录
└── 设置
    ├── 站点账号：中文站 / 国际站
    └── 存储与下载：目录、格式、并行任务数

统一主操作：添加模型
├── 模型链接 → 自动识别站点
├── 本地模型 → 新建资料、模型文件和展示图片
└── 用户主页
    ├── 目标用户：当前登录账号 / 指定用户
    ├── 当前登录账号：收藏的模型 / 发布的模型
    └── 指定作者：公开发布的模型
```

## 保留的功能边界

- **模型库和下载任务保留为两个页面**：前者浏览内容，后者处理传输进度与失败；“下载完成记录”不替代“已下载模型”。
- **中文站和国际站保留两套连接**：属于两个来源及登录状态，不能因去重而混用会话。当前原型按站点分别导入。
- **当前账号保留收藏和发布两个范围**：指定作者只支持公开发布模型，避免把站点不公开的他人收藏误作可导入能力；它们共用清单预览与下载流程。
- **Inspector 保留单模型下载**：已有明确模型时无需重新粘贴链接，复用同一队列能力。
- **完整图文介绍**：正文与插图按原顺序展示，优先读取已归档图片；任务未完成时，详情与卡片显示同一状态，并可进入任务页处理。
- **缺少登录时保留就地连接提示**：为当前导入补齐前置条件，并非新增账号管理模块。
- **Appica V2 已选定**：原生应用采用当前确认稿，不包含方案切换条；A/B/C 和 Native Glass 仅保留为设计历史。

## 未纳入本轮的扩展

作者订阅和自动追更、自定义收藏夹、云同步、重复文件清理和三维预览均不在本轮范围内。先把双站点获取、完整归档和本地阅读做好。

## 本轮检查范围

按项目要求，不编译、不运行测试用例、不提交 Git。通过代码、页面结构和 MakerWorld 当前网页请求检查接口；登录态收藏与实际文件下载仍需在应用内使用真实账号手工验证。
