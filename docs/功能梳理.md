# MakerShelf 功能梳理与去重

## 核心范围

从 MakerWorld 中文站和国际站获取本人收藏、本人发布内容、指定作者公开作品或单个链接对应的模型，下载后在本地查看模型文件、原始介绍与图片。

这份文档记录各功能的职责。应用采用 SwiftUI 原生界面，支持站点登录页、模型链接解析和本地归档写入。收藏 / 作品批量列表与部分文件下载仍取决于登录会话和站点接口稳定性。

## 重复项处理

| 原有功能 / 入口 | 问题 | 整理结果 |
| --- | --- | --- |
| 同步收藏、新增下载、导入窗口里的我的收藏 | 多个名称进入同一套下载流程 | 统一“添加模型”；本人收藏是用户导入条件之一 |
| 侧栏模型来源、模型库顶部来源筛选 | 都是在同一模型列表中过滤来源 | 删除侧栏中文站 / 国际站 / 本地模型三个入口，只保留顶部筛选 |
| 指定账号、作者作品 | 都通过用户 ID 或主页定位用户，只是获取内容不同 | 合并“用户主页”；分别选择目标用户和获取内容 |
| 全部模型、已下载 | 同一模型列表的两个筛选视图 | 合并“模型库”，提供全部 / 已下载 / 未下载筛选 |
| 关注的作者、作者搜索 | 目前没有关注管理，仅按作者查看已有模型 | 删除独立作者页，保留作者筛选和关键词搜索 |
| 本地我的收藏、卡片心形按钮、站点收藏 | “收藏”同时表示两种数据，容易误认为修改源站收藏 | 删除额外的本地收藏；“收藏”只表示导入的站点内容 |
| 桌面灵感、模型分类 | 预设集合实际只是按分类过滤，未提供集合管理 | 移除预设集合，保留分类筛选 |
| 顶栏设置、工作空间按钮、站点卡片、账号管理 | 同一设置能力散落多个入口 | 设置页集中管理双站点连接；侧栏不再展示来源或连接菜单 |
| 导入时勾选介绍/图片、设置中的媒体开关 | 重复决定归档内容，也容易遗漏用户明确需要的信息 | 固定完整归档：文件 + 介绍 + 图片 |
| 查看本地归档按钮、归档信息标签 | 按钮只切到同一个标签，没有独立能力 | Inspector 保留归档标签；真实归档可直接在访达中显示 |

## 最终结构

```text
MakerShelf
├── 模型库
│   ├── 搜索 / 来源 / 作者 / 分类 / 下载状态
│   ├── 网格或列表
│   └── 右侧 Inspector：图片、介绍、文件、归档信息
├── 下载任务
│   └── 进度、暂停、继续、完成记录
├── 运行日志
│   └── 搜索、级别与模块筛选、展开复制、导出与清空
└── 设置
    ├── 站点账号：中文站 / 国际站
    └── 存储与下载：目录、归档恢复、格式、并行任务数、STL 预览预算

统一主操作：添加模型
├── 模型链接 → 自动识别站点
├── 本地模型 → 新建资料、模型文件和展示图片
└── 用户主页
    ├── 目标用户：当前登录账号 / 指定用户
    ├── 当前登录账号：收藏的模型 / 发布的模型
    └── 指定作者：公开发布的模型
```

## 保留的功能边界

- **模型库和下载任务保留为两个页面**：前者浏览内容，后者处理传输进度与失败；“下载完成记录”不替代“已下载模型”。
- **中文站和国际站保留两套连接**：属于两个来源及登录状态，不能因去重而混用会话。应用按站点分别导入。
- **当前账号保留收藏和发布两个范围**：指定作者只支持公开发布模型，避免把站点不公开的他人收藏误作可导入能力；它们共用清单预览与下载流程。
- **Inspector 保留单模型下载**：已有明确模型时无需重新粘贴链接，复用同一队列能力。
- **完整图文介绍**：正文与插图按原顺序展示，优先读取已归档图片；任务未完成时，详情与卡片显示同一状态，并可进入任务页处理。
- **缺少登录时保留就地连接提示**：为当前导入补齐前置条件，并非新增账号管理模块。

STL / OBJ 支持完整网格的固定视角几何缩略图与放大查看，预算充足时启用超采样抗锯齿；3MF 继续读取包内预览，三者均可作为本地模型封面候选。STEP / STP 仍需 CAD 网格化，当前显示格式占位，不借用其他文件预览或模型封面。运行日志是诊断入口，不替代下载任务的进度与操作。

## 更新或重装后的归档恢复

此功能从 2.1 开始提供。目标是恢复已经由 MakerShelf 管理的模型，不将现有模型重新复制成新藏品。

入口位于空模型库的「找回已有模型」和「设置 → 存储与下载 → 找回已有模型」。通过系统选择器重新授权原归档总目录后，扫描其中的 metadata.json；已授权时可直接扫描当前目录。启动时只在索引为空或不可读、且已保留目录授权的情况下自动尝试一次。

### 数据与任务边界

1. `ArchiveRecoveryScanner` 在独立 actor 中扫描归档，兼容站点旧版精简资料与完整 ModelRecord。实际 models / images 文件决定恢复后的路径，旧机器的绝对路径不参与读取。介绍优先读取原 description.html。
2. 保留模型 ID、来源、作者、封面顺序和已有资料；旧版精简格式缺失的分类等字段优先保留当前索引值，没有原索引时使用默认值并报告。后续站点下载与本地归档统一写入完整资料。
3. `ModelCatalog.restoreArchives` 按 ID 合并，未扫描到的原有记录不删除，重复恢复不新增重复卡片。相同 ID 出现在多份有效归档时全部跳过并提示整理，不任意选择其中一份。
4. 索引损坏不再静默返回空库；恢复前将损坏的 library.json 备份到同一应用数据目录，再原子保存合并结果。备份失败会停止；保存失败会回滚内存状态。
5. `ArchiveRecoveryStore` 统一管理启动恢复、手工恢复、取消与结果。切换页面保留任务；选择其他根目录会取消旧扫描，旧任务不得回写新目录的结果。扫描有独立目录访问生命周期。

原模型、图片、介绍和 metadata.json 均不复制、不移动、不改写。普通散装目录、没有有效资料的归档、没有任何现存模型文件的记录无法从此入口恢复。单个模型目录不能作为归档总目录，以免后续编辑时把整个根目录当成一份模型替换。

扫描忽略隐藏目录、软件包和符号链接，限制为 20 万个目录条目、1 万份模型资料、64 层目录；每份资料 / 介绍最多 8 MiB，累计最多读取 128 MiB 文档。超出整批限制时停止且不提交部分索引；单份损坏资料会单独记录，其他有效模型仍可恢复。页面最多显示 50 条扫描提示，完整详情进入运行日志。

发布整理检查了源码调用、工程引用和文档一致性；未在本机重新编译、运行测试或修改用户现有归档。安装包由 GitHub Actions 构建。

## 未纳入本轮的扩展

作者订阅和自动追更、自定义收藏夹、云同步、重复文件清理和交互式三维预览均不在本轮范围内。先把双站点获取、完整归档和本地阅读做好。

## 验证边界

2.1 发布整理未在本机重新编译或运行测试用例；发布工作流负责生成未签名安装包。登录态收藏、实际下载、大模型预览效果和升级流程仍需在目标设备使用真实数据验收。
