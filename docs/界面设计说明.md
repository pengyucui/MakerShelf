# MakerShelf 界面设计说明

## 当前采用：Appica V2

用户已确认采用 [Appica V2 效果图与实现说明](界面设计-Appica-V2.md)，当前 SwiftUI 源码已完成对应调整。侧栏只保留模型库、下载任务、设置，来源筛选统一在模型库顶部；封面统一 4:3，右侧详情可收起，底部展示真实下载状态。整体使用白卡片、深墨色按钮和轻毛玻璃。按要求尚未编译、启动验收或发布。

下文的方案 A、Native Glass、Figma 链接和网页原型均为历史设计记录，颜色与布局细节不再作为当前实现标准。

## 设计目标

为中文站和国际站的 MakerWorld 收藏提供一个统一的本地入口。用户首先看到收藏的作品，而不是文件目录；每份模型的介绍、作者、来源和图片都与文件一起保留。

本轮回答的问题：哪种界面最适合“收藏作品、批量下载、长期本地浏览”？项目原先为空，因此使用独立 `prototype/` 路径提供三个对比方案。用户现已选择方案 A，并已新增原生 SwiftUI 实现；B/C 仅保留为网页设计历史。原生实现说明见 [SwiftUI 架构与性能](SwiftUI架构与性能.md)。

## Native Glass 重设计方向

新版确认稿把方案 A 进一步收敛为原生 macOS 信息结构：标准 Title Bar、半透明侧栏、紧凑工具栏、模型网格和常驻右侧 Inspector。该结构已经落入 SwiftUI 主窗口；选中卡片即可在 Inspector 中切换图片、介绍、文件和归档信息，浏览位置不会丢失，也不再打开另一层大型详情弹窗。

“添加模型”使用居中的原生 Sheet，用户主页、模型链接和本地模型仍是同一个流程。本地模型表单在左侧选择文件、图片并填写资料，右侧实时显示模型库卡片预览与归档位置。已归档模型都可以编辑：Inspector 底部固定显示“编辑本地模型”，卡片提供「编辑」和右键菜单；编辑页以同一套双栏表单回填并更新现有内容。主窗口信息结构对齐 Native Glass：工具栏搜索、来源分段、右侧 Inspector 与侧栏来源筛选。该部分已使用 SwiftUI `sheet`、`fileImporter`、文件拖放和现有本地导入服务落地；保存操作使用分阶段归档替换流程。

材质层级只使用三档：侧栏 `.ultraThinMaterial`、Inspector / 工具栏 `.thinMaterial`、Sheet / 卡片 `.regularMaterial`。主要内容保持低透明度系统语义背景，确保模型图片和长文字的可读性。模型卡片使用固定封面区与固定总高度，任何图片比例都不会改变网格行高。新版使用 SF Pro 系统字体、SF Symbols、系统分段控件和按钮尺寸，不再采用网页式大统计卡片。

下载任务页使用紧凑指标卡、归档位置卡和统一任务行；设置页使用响应式账号卡与存储面板；用户主页、模型链接和本地模型共享同一个宽版 Sheet、标题栏与分段入口。三个主页面与导入流程复用同一套 `GlassPanel`、按钮、提示条和空状态组件，避免每个页面形成不同视觉语言。

确认稿位于 `prototype/native-glass.html`，Figma 文件为 [MakerShelf macOS · Native Glass Redesign](https://www.figma.com/design/pVFk7WDb4x9SrsTGTPlNe2)。

## 三个方案

| 方案 | 信息结构 | 适合场景 |
| --- | --- | --- |
| A · 本地工作台，推荐 | 固定左侧导航、双站点状态、分类筛选、四列模型网格、图文详情浮层 | 平衡日常浏览与下载管理 |
| B · 灵感画廊 | 横向导航、编辑式大幅作品展示、三列大图画廊 | 更看重图片、灵感收集与模型介绍 |
| C · 下载控制台 | 深色紧凑导航，默认进入任务总览和队列，模型库默认列表 | 经常按作者或账号批量导入 |

三种方案复用演示数据和导入流程，但调整了导航位置、默认入口、图片尺寸及信息层级。底部方案切换条只用于本轮设计比较，正式产品不保留。选定后应重新梳理正式页面结构，删除未采用的原型方案。

## 视觉规范

- 暂定名称：MakerShelf；中文定位：你的本地模型馆。
- 主色：森林绿 `#326D50`；侧栏：浅鼠尾草绿；内容区域：暖白。
- 主界面采用 macOS 风格的侧栏、轻边框、小圆角与系统中文字体。
- 模型图片优先，辅助信息轻量呈现；状态同时使用文字与图标，不只依赖颜色。
- 8 个示例模型均为本地原创造型插画，不是来自真实站点的照片或下载成果。
- 模型网格按内容宽度自适应列数；Inspector 保持固定信息宽度，卡片封面与总高度一致。
- 保留键盘焦点提示、弹窗焦点约束、Escape 关闭、快捷搜索与减少动画偏好。

## 信息架构

### 统一模型库

侧栏仅有模型库、下载任务、设置。模型库统一承载封面、名称、作者、格式、来源站点和归档状态，支持关键词搜索、分类、来源、作者、下载状态筛选，以及网格和列表切换。

“全部模型”和“已下载”是同一份数据的不同筛选条件，不再建立重复页面。“关注的作者”并没有独立关注能力，改为作者筛选；“桌面灵感”预设页移除。页面间跳转保留筛选条件，重置筛选按钮统一清空。

不提供第二套本地收藏按钮。“收藏”专指 MakerWorld 上的收藏内容，通过统一导入操作获取；本地以模型库、分类和搜索整理。完整去重映射见 [功能梳理](功能梳理.md)。

### 模型详情

详情整合进模型库右侧 Inspector：顶部显示封面与多图切换，下方显示名称、作者、来源、文件数量、大小与本地状态，三个标签分别承载作品介绍、模型文件和归档信息。未下载模型可直接开始下载；真实归档模型可直接在访达中显示；来源站点提供链接时可从介绍页打开。

应用保留作者原文和完整图片序列，并显示打印配置、来源链接与许可信息（源站提供时）。示例模型只使用内置原创造型图片和示例文件名，不声称包含真实可打印文件。

### 设置 / 站点账号

账号连接与存储下载偏好集中在同一个设置页的两个标签中；侧栏站点卡片仅展示连接状态。中文站和国际站独立展示连接状态。正式页面应区分：未连接、登录中、已连接、登录过期、连接失败。

应用使用站点自己的登录页面，让用户完成登录，不读取密码。会话凭据保存在本应用的数据保护钥匙串，不放进模型归档目录，中文站与国际站隔离管理。安装后钥匙串只需授权一次；启动本地模型库时不读取钥匙串，进入账号页或执行联网操作时按需恢复到内存，之后不再弹授权。

### 统一导入窗口

页面只保留一个“导入模型”主操作，不再同时展示“同步收藏”和“新增下载”。模型库与任务页上的同名按钮都是同一个导入流程的上下文入口。

| 来源类型 | 输入 | 获取内容 |
| --- | --- | --- |
| 模型链接 | 模型详情链接，自动识别站点 | 对应模型的可下载文件 |
| 用户主页 | 选择当前登录账号，或输入指定作者用户名、用户 ID / 主页链接 | 当前账号的收藏 / 发布模型，或指定作者的公开发布模型 |

“当前登录账号 + 收藏的模型”覆盖自己的收藏同步；当前账号也可读取自己的发布模型；指定作者只读取其公开发布模型。作者主页链接自动识别站点，用户名和 `@用户名` 会先解析为数字 UID。三类范围共享清单预览和下载逻辑。

完整流程：选择来源 → 公开内容直接预览 / 当前账号内容检查登录 → 获取并分页列出内容 → 勾选模型 → 加入下载队列 → 下载时检查对应站点登录。中文站和国际站使用各自登录状态。模型、介绍、图片固定完整归档，不再在导入页和设置页提供重复开关。

原型中的清单为固定示例，范围选择只用于表达导入意图，不会实际解析账号。真实版本需展示分页进度、已发现与可下载数量、重复项和不可访问原因，不能提前宣称已获取全部内容。

### 下载管理

每个任务聚合模型文件、介绍、图片三个归档步骤。可暂停单个任务或全部任务，恢复后继续。正式版建议展示以下状态：

`等待处理 → 获取文件信息 → 下载模型 → 保存介绍与图片 → 校验文件 → 已完成`

异常状态：登录过期、权限不足、链接失效、请求受限、磁盘空间不足、部分失败。模型已下载但图片失败应显示“部分完成”，保留成功文件，仅重试失败部分。当前仅演示进度、暂停和完成，未实现这些异常分支。

### 本地归档建议

```text
模型库/
  站点/
    作者名_作者ID/
      模型名_模型ID/
        models/              模型与打印配置文件
        images/              封面和展示图片
        description.html     清理后的模型介绍，图片指向本地
        metadata.json        来源、作者、版本、许可与归档时间
```

本地索引以站点与模型 ID 标识模型，文件层面使用文件 ID、版本及校验值判断重复。跨站同名不自动合并。模型文件、说明和图片都落盘后，离线状态下仍能完整阅读详情。

## 后续开发顺序

1. 确定视觉方向与必要页面，收敛当前原型。
2. 分别验证中文站、国际站的实际登录、收藏读取、作者作品分页和文件下载流程。
3. 打通单模型完整归档：文件、介绍、图片、元信息、本地阅读。
4. 扩展到收藏与作者批量归档，加入分页、去重、限速、暂停和失败重试。
5. 完成真正的离线模型库、搜索与文件索引，再封装 macOS 客户端并接入原生文件选择与系统能力。

客户端技术栈已确定为 macOS 14+ SwiftUI，已建立 Xcode 工程与原生页面。没有进行编译、运行测试用例或 Git 提交；真实站点接入仍待实现。
